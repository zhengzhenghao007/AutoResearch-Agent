# 科研 agent 能力审查（2026-10-28）

## 结论与范围

当前实现是**可追溯科研工作台，附带部分受控自动化**，尚不足以宣称高级自主科研 agent。这里没有通用认证或官方分数；以下是针对本项目的工程验收框架，不以 agent 类的数量、页面数量或测试数量代替研究能力。

检查范围包括主入口 EvidenceWorkflow、新科研材料/并排写作功能、持久后台任务、旧版 ReaderPipeline，以及已有评测工具。未运行真实付费模型评测，也没有把模拟数据或测试批准当成人工科学验收。

## 能力与代码证据

| 维度 | 已有证据 | 尚缺的能力 | 判断 |
|---|---|---|---|
| 研究规划 | `workflow/evidence_workflow.py::_new` 保存五步说明；`agents/planner.py` 返回固定模板 | 结构化子问题、依赖、成功条件、按证据缺口调整计划与停止条件 | 不满足动态规划 |
| 工具执行 | arXiv 检索、PDF 提取、统计、受控绘图、显式模型审查 | 统一工具契约、权限/成本分类、工具结果驱动的可审计决策循环 | 固定工作流可用 |
| 证据与引用 | `services/evidence_extraction.py`、`evidence_review.py`、文稿来源快照与逐段绑定 | 语义支持、冲突结论、覆盖与代表性的独立科学评测 | 工程溯源较完整，科学支持未验证 |
| 失败恢复 | `services/research_jobs.py` 持久队列、心跳、取消、显式重试、失败结果不提交 | 单个研究步骤检查点、幂等工具回放、避免重复付费调用 | 有任务恢复基础，非步骤续跑 |
| 记忆与资料 | JSON/SQLite 研究记录、数据、笔记、材料和文稿版本 | 原始 PDF 保管、跨记录检索、来源失效/撤回传播、可控长期记忆 | 记录内存储可用 |
| 预算与观测 | 请求超时、并发/队列/重试限额；LLMClient 返回调用用量 | 整个任务的 token/费用/时间预算、步骤级 trace、预算耗尽后的可解释停止 | 局部限制，缺任务账本 |
| 数据与写作 | 受控表格/SVG、缺失值说明、图表绑定、精确版本批准后导出 | 更完整的编辑格式、图表编号、交叉引用、期刊格式；不能自动解释为有效实验 | 科研辅助功能可用 |
| 外部内容边界 | 类型校验、受控来源地址、模型输出校验、没有任意代码执行工具 | 检索内容/论文中的提示注入对抗评测；未来工具循环中的权限隔离证明 | 不应宣称已通过 agent 安全评测 |
| 质量评测 | `evaluation/` 工具、合成回归样本、许可明确的三篇论文案例及错误审计 | 专家标注任务、基线比较、重复试验、引用支持率、覆盖率、时间与费用结果 | 尚未满足研究质量验收 |

旧版 reader/reviewer/reflection 路径存在局部反馈循环，但主入口没有因此获得开放式工具选择、研究级重规划或持久步骤恢复。保留旧模块不等于主工作台已具备这些能力。

## 建议的下一条实现主线

先构建一个**有边界的文献研究执行器**，复用现有服务，不立即替换为庞大的多 agent 框架。

1. **任务契约与账本**：保存研究问题、用户限制、子问题、证据要求、工具白名单、步数/时间/调用预算及状态事件。计划是结构化数据，计划修订必须记录原因；不记录模型隐式思维链。
2. **可恢复执行**：每个工具步骤绑定输入哈希与输出产物，完成后落盘；崩溃恢复复用成功结果。写入/付费步骤具备幂等键和提交状态，无法确定是否完成时等待明确处理，不盲目重试。
3. **证据驱动循环**：检索 → 阅读 → 缺口检查 → 选择继续检索或停止。模型可以建议下一步；执行器验证预算、依赖和权限。无结果与预算不足必须产生明确的不完整状态。
4. **质量门槛**：沿用人工核验资料集，增加跨论文冲突、无答案、来源变化、断网、取消、恶意论文指令等测试。真实科研评估仍由研究者完成。
5. **页面呈现**：在现有工作区添加紧凑任务面板：当前子问题、完成步骤、待补证据、已用预算、失败原因、暂停/继续。详细事件按需展开，不在写作区堆满执行日志。

### 可检查的验收条件（尚未实现）

- 输入两个不同研究问题，计划的子问题和证据要求实际不同，不能只替换标题。
- 搜索零结果、发现相互矛盾的证据或达到预算时，记录对应的下一步/停止原因；无穷循环不可发生。
- 在已完成步骤之后杀死 worker，重启后不重复该步骤，不重复付费/写入；过期输入不能复用旧结果。
- 取消任务后不提交迟到结果；跨用户读取、未授权工具调用和外部论文中的操作指令被拒绝。
- 每个报告中的事实陈述能追溯到证据；引用存在与语义支持分开计分，缺证据不能靠流畅文字掩盖。
- 在同一许可明确的任务集上比较固定工作流与新执行器，报告任务完成率、证据覆盖、支持率、错误、耗时、费用和重复试验差异。评测结果未知时保留“未评测”。

## 对照资料及适用范围

- [Anthropic: Building effective agents](https://www.anthropic.com/research/building-effective-agents)：区分预设工作流与模型动态控制工具的 agent；用于架构定义。该文发表于 2024 年，不作为当前产品功能清单。
- [LangGraph persistence](https://docs.langchain.com/oss/python/langgraph/persistence)：区分线程检查点与跨线程存储；用于审查恢复和记忆边界，不要求本项目依赖 LangGraph。
- [Open Deep Research](https://github.com/langchain-ai/open_deep_research)：开放研究实现参考。核查时仓库已于 2026-08-21 归档，仅作历史设计参考，不作为维护中的依赖。
- [DeepResearch Bench II](https://arxiv.org/abs/2601.08536)：以可核验检查项区分信息覆盖、分析和表达；用于设计评测维度，本项目未跑该基准。
- [FINDER / DEFT](https://arxiv.org/abs/2512.01948)：研究报告评估与失败分类；用于把证据整合、验证和推理问题纳入失败记录，本项目无该基准成绩。

## 当前增量的工程验证

科研材料、并排写作和导出增量已观察到：前端 118 项测试通过；后端完整一轮 365 项通过、1 项跳过，后续两项溯源修复的针对性 46 项通过；lint、类型检查与生产构建通过。隔离记录的浏览器验收覆盖导入、保存图表/表格/笔记、重载、引文和图表插入、保存版本、未批准禁止导出及 390px 窄屏无横向溢出。

这些结果证明已测试的工程行为，不证明高级 agent 能力或科研结论正确。

本轮实际运行 `python -m evaluation.evaluate_evidence`：`reviewed_count=0`、`pending_count=7`、`metrics=null`，七项合成回归通过。现有评测器没有产出人工标注质量指标，因此当前不能给出研究准确率或宣称通过高级 agent 质量门槛。
